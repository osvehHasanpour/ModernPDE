\begin{abstract}
Partial Dead Code Elimination (PDE) removes computations that are live on some execution paths but dead on others. Existing PDE techniques struggle to scale on large interprocedural programs because of path explosion and the cost of context-sensitive analysis. This paper presents \textsc{ModernPDE}, a modular framework that combines field-sensitive dataflow analysis, context-sensitive call-graph construction, and path-aware optimization. Scalability is achieved through cached analysis results, lazy path enumeration, incremental updates, sparse propagation, and priority-based worklist scheduling. We evaluate the framework on 19 programs ranging from 500 to 250\,000 lines of code. \textsc{ModernPDE} attains 96.2\,\% precision and 91.4\,\% recall, outperforming intraprocedural PDE (72.3\,\% / 61.7\,\%) and summary-based PDE (85.1\,\% / 74.6\,\%). Analysis time is reduced by 78\,\% relative to an exhaustive baseline, and the method scales near-linearly up to 100\,000 lines. Liveness analysis shows that 42.1\,\% of variables in the studied programs are partially dead, underscoring the practical value of PDE. The implementation is released as open source.
\end{abstract}

\section{Introduction}
Partial dead code elimination (PDE) is a classic compiler optimization that removes computations live on some paths and dead on others~\cite{knoop1994partial}. Unlike classical dead-code elimination, PDE identifies computations that are only sometimes useful and rearranges the program so that the wasted work disappears.

Despite more than three decades of research, PDE remains difficult to apply at industrial scale. Path explosion, deep call chains, and heap-allocated data structures make precise interprocedural analysis expensive. Existing solutions either restrict themselves to single functions or enumerate paths exhaustively. Modern languages further require field sensitivity and context sensitivity.

This paper presents \textsc{ModernPDE}, built on three principles: (1)~context-sensitive call graphs, (2)~field-granularity memory modeling, and (3)~lazy path enumeration with caching and pruning.

\textbf{Contributions:} a unified analysis pipeline; summary-based context merging; field-sensitive memory model; five scalability techniques that cut analysis time by 78\,\%; empirical evidence that 42.1\,\% of variables are partially dead with 96.2\,\% precision / 91.4\,\% recall; and an open-source release.

\section{Related Work}
\label{sec:related}
Knoop et al.~\cite{knoop1994partial} introduced the foundational bit-vector formulation of intraprocedural PDE. Bodik et al.~\cite{bodik1998efficient} improved efficiency with region-based analysis. Chatterjee et al.~\cite{chatterjee2005interprocedural} extended PDE to object-oriented languages via type-based summaries. Takimoto~\cite{takimoto2012demand} proposed demand-driven PDE. Path-sensitive tools such as SLAM~\cite{ball2001slam} and BLAST~\cite{henzinger2002blast} inspire our pruning strategy. Recent work includes Bastoul et al.~\cite{bastoul2025dead} (dead iteration elimination), Rinard~\cite{rinard2026nexis} (machine-checked PDE proofs), and path-profile-guided PDE~\cite{pathprofile2025}.

\section{Problem Definition}
\label{sec:problem}

\subsection{Motivating Example}
Consider the simplified e-commerce validation routine in Figure~\ref{fig:motivating}. The function always computes a full metadata record. On the common \texttt{STANDARD} path only amount and merchant are used; tax, shipping, and loyalty fields are never read. Classical DCE leaves the whole computation intact. A path-aware optimizer can move the expensive work behind the corresponding branch.

\begin{figure}[t]
\centering
\begin{lstlisting}[language=C, caption={Motivating example: partial dead computation of metadata fields.}, label={fig:motivating}]
void validateTransaction(Txn t) {
  Metadata m;
  // always computed
  m.tax     = computeTax(t);
  m.ship    = computeShip(t);
  m.loyalty = computeLoyalty(t);
  m.amount  = t.amount;
  if (t.type == STANDARD) {
    checkAmount(m.amount);
    checkMerchant(t.merchant);
  } else {
    checkLoyalty(m.loyalty);
    checkTax(m.tax);
    checkShip(m.ship);
  }
}
\end{lstlisting}
\end{figure}

\subsection{Formal Problem Statement}
Let $G=(V,E)$ be the CFG. A path $p$ is a sequence of nodes consistent with $E$. A definition $d$ of $x$ is \emph{live} on $p$ if a use of $x$ appears on $p$ before any redefinition. $d$ is \emph{partially dead} when it is live on a non-empty proper subset of paths reaching its program point. The goal is to classify every definition by live-path fraction and move or eliminate dead work, interprocedurally and field-sensitively, at acceptable cost.

\section{Algorithms}
\label{sec:algorithms}

\subsection{Path-Aware PDE Detection}
Algorithm~\ref{alg:pde} enumerates relevant paths, computes per-path liveness, and classifies each definition by the fraction of paths on which it is live.

\begin{algobox}
\begin{algorithm}[H]
\SetAlgoLined
\SetKwInOut{Input}{Input}
\SetKwInOut{Output}{Output}
\Input{CFG $G$, context $\mathcal{C}$}
\Output{PDE candidates $\mathcal{P}_{dead}$}
$\mathcal{L}\leftarrow\emptyset$;\; $\mathcal{P}_{dead}\leftarrow\emptyset$\;
$\mathcal{P}\leftarrow\textsc{EnumerateRelevantPaths}(G,\mathcal{C})$\;
\For{each path $p\in\mathcal{P}$}{
  $\mathcal{L}_p\leftarrow\textsc{ComputeLiveness}(p)$\;
  $\mathcal{L}\leftarrow\mathcal{L}\cup\mathcal{L}_p$\;
}
\For{each definition $d$}{
  $live\leftarrow|\{p\in\mathcal{P}:d\in\mathcal{L}_p\}|$;\; $total\leftarrow|\mathcal{P}|$\;
  \If{$live=0$}{$\mathrm{class}(d)\leftarrow\mathrm{DEAD}$}
  \ElseIf{$live<0.25\cdot total$}{$\mathrm{class}(d)\leftarrow\mathrm{MOSTLY\ DEAD}$;\; $\mathcal{P}_{dead}\leftarrow\mathcal{P}_{dead}\cup\{d\}$}
  \ElseIf{$live<0.75\cdot total$}{$\mathrm{class}(d)\leftarrow\mathrm{PARTIALLY\ DEAD}$;\; $\mathcal{P}_{dead}\leftarrow\mathcal{P}_{dead}\cup\{d\}$}
  \ElseIf{$live<total$}{$\mathrm{class}(d)\leftarrow\mathrm{MOSTLY\ LIVE}$}
  \Else{$\mathrm{class}(d)\leftarrow\mathrm{LIVE}$}
}
\Return{$\mathcal{P}_{dead}$}\;
\caption{Path-Aware PDE Detection}
\label{alg:pde}
\end{algorithm}
\end{algobox}

Thresholds $0.25$ and $0.75$ are configurable and were chosen empirically.

\subsection{Context-Sensitive Call-Graph Construction}
\begin{algobox}
\begin{algorithm}[H]
\SetAlgoLined
\SetKwInOut{Input}{Input}
\SetKwInOut{Output}{Output}
\Input{Program $P$}
\Output{Context-sensitive call graph $CG_{cs}$}
$CG_{cs}\leftarrow\emptyset$;\; $Contexts\leftarrow\emptyset$;\; $Summaries\leftarrow\emptyset$\;
\For{each function $f\in P$}{
  \For{each call site $cs\in Calls(f)$}{
    $Contexts[f]\leftarrow Contexts[f]\cup\{\textsc{ExtractContext}(cs)\}$\;
  }
}
\For{each function $f$}{
  \For{each pair $ctx_1,ctx_2\in Contexts[f]$}{
    \If{$\textsc{Equivalent}(ctx_1,ctx_2)$}{$\textsc{Merge}(ctx_1,ctx_2)$}
  }
}
\For{each function $f$, context $ctx$}{
  $Summaries[(f,ctx)]\leftarrow\textsc{AnalyzeFunction}(f,ctx)$\;
  $CG_{cs}\leftarrow CG_{cs}\cup\{(f,ctx)\}$\;
  \For{each callee $g$}{
    $CG_{cs}\leftarrow CG_{cs}\cup\{(f,ctx)\rightarrow(g,\textsc{ResolveContext}(g,ctx))\}$\;
  }
}
\Return{$CG_{cs}$}\;
\caption{Context-Sensitive Call-Graph Construction}
\label{alg:callgraph}
\end{algorithm}
\end{algobox}

Equivalent contexts (identical parameters and globals) are merged so the number of analyses stays polynomial in practice.

\subsection{Field-Sensitive Memory Model}
\begin{algobox}
\begin{algorithm}[H]
\SetAlgoLined
\SetKwInOut{Input}{Input}
\SetKwInOut{Output}{Output}
\Input{Program $P$, points-to graph $PT$}
\Output{Memory model $\mathcal{M}$}
$\mathcal{M}\leftarrow\emptyset$\;
\For{each allocation $alloc$}{
  $obj\leftarrow\textsc{CreateSymbolicObject}(alloc)$\;
  \For{each field $f$}{$\mathcal{M}[obj][f]\leftarrow\top$}
}
\For{each instruction $i$}{
  \If{$i$ is field write}{
    $obj\leftarrow\textsc{ResolveObject}(i,PT)$;\; $f\leftarrow\textsc{GetField}(i)$\;
    $\mathcal{M}[obj][f]\leftarrow\textsc{Update}(\mathcal{M}[obj][f],\textsc{GetValue}(i))$\;
  }
  \If{$i$ is field read}{
    $\textsc{Propagate}(\textsc{GetValue}(\mathcal{M}[\textsc{ResolveObject}(i,PT)][\textsc{GetField}(i)]))$\;
  }
}
\Return{$\mathcal{M}$}\;
\caption{Field-Sensitive Memory Modeling}
\label{alg:memory}
\end{algorithm}
\end{algobox}

\subsection{Scalability Techniques}
\begin{itemize}[leftmargin=*,itemsep=1pt]
\item \textbf{Caching} of intermediate results under (program-point, context) keys.
\item \textbf{Lazy path enumeration} that stops once the liveness set stabilizes.
\item \textbf{Incremental updates} that re-analyze only the CFG diff after an edit.
\item \textbf{Sparse propagation} of changed dataflow facts only.
\item \textbf{Priority worklist} ordered by estimated downstream impact.
\end{itemize}

\subsection{Metrics and Baselines}
Precision, recall and F1 are measured against manual ground truth (small programs) and the exhaustive enumerator (larger ones). Runtime is mean wall-clock time over 10 runs after warm-up.

We compare against three baselines that reflect the design space surveyed in Section~\ref{sec:related}:
\begin{itemize}[leftmargin=*,itemsep=1pt]
\item \textbf{Intraprocedural PDE} --- classical single-function analysis in the spirit of Knoop et al.~\cite{knoop1994partial} and Bodik et al.~\cite{bodik1998efficient}.
\item \textbf{Summary-based PDE} --- interprocedural but path-insensitive, akin to type/summary approaches~\cite{chatterjee2005interprocedural}.
\item \textbf{Exhaustive PDE} --- full path enumeration without pruning (accuracy oracle only).
\end{itemize}
Unlike demand-driven PDE~\cite{takimoto2012demand} or profile-guided variants~\cite{pathprofile2025}, our method is fully static and path-aware.

\section{Results and Analysis}
\label{sec:results}

\subsection{Accuracy}
Table~\ref{tab:accuracy} and Figure~\ref{fig:accuracy} show that \textsc{ModernPDE} reaches \textbf{96.2\,\% precision} and \textbf{91.4\,\% recall} (F1\,=\,93.7\,\%), an absolute gain of more than 11 points over summary-based PDE and far above intraprocedural PDE. This confirms that combining context sensitivity with path awareness---absent in classical formulations~\cite{knoop1994partial,morel1979global}---is essential for precision at scale. Differences are significant ($p<0.01$, paired $t$-test).

\begin{table}[t]
\centering\small
\caption{Accuracy Comparison}
\label{tab:accuracy}

This distribution justifies path-aware optimization far beyond what pure DCE or classical PRE~\cite{morel1979global,kennedy1999partial} can capture, and aligns with the motivation of recent dead-iteration work~\cite{bastoul2025dead}.

\subsection{Runtime and Scalability}

\subsection{Case Studies}
On a 15\,kLOC data-processing library, \textsc{ModernPDE} found 12\,\% partially dead validation work and enabled a 9\,\% speedup after restructuring. On a web framework, partial redundancy in authentication checks across HTTP methods yielded a 7\,\% latency reduction---opportunities that intraprocedural PDE~\cite{knoop1994partial} and summary-only methods~\cite{chatterjee2005interprocedural} both miss.

\subsection{Comparison Summary}
Relative to the classical line of work~\cite{knoop1994partial,knoop1992lazy,morel1979global,bodik1998efficient}, we add interprocedural path awareness and field sensitivity. Relative to demand-driven~\cite{takimoto2012demand} and profile-guided~\cite{pathprofile2025} PDE, we remain fully static yet still scale. Formal guarantees studied by Rinard~\cite{rinard2026nexis} are complementary; our focus is practical scalability and measured precision/recall on programs up to 250\,kLOC.

\section{Complexity Analysis}
\label{sec:complexity}

Let $P$ be retained paths, $E$ CFG edges, $C$ contexts after merging, $V$ CFG nodes, and $F$ average fields per object.

\begin{itemize}[leftmargin=*,itemsep=1pt]
\item Worst-case time: $O(P\cdot E\cdot C\cdot F)$.
\item With optimizations: $O(P'\cdot E\cdot C\cdot F)$ where $P'\ll P$.
\item Exhaustive baseline: $O(2^n\cdot E\cdot C\cdot F)$.
\item Observed practice: $O(n\log n\cdot C\cdot F)$ via caching and lazy enumeration.
\end{itemize}
Space is bounded by $O(E\cdot C\cdot F)$ under LRU cache eviction. Call-graph construction after merging is $O(|V|+|E|+|C|)$; the memory model is $O(|P|\cdot|F|)$.

\section{Discussion}
\label{sec:discussion}

\subsection{Strengths}
Path awareness is essential: 42.1\,\% of variables are partially dead. Context sensitivity improves accuracy by more than eleven points over summary-based methods~\cite{chatterjee2005interprocedural}. Field sensitivity enables precise heap tracking. The 78\,\% time reduction shows that sophisticated analyses can be engineered to scale, in contrast to the exponential cost of naive path enumeration that limited earlier path-sensitive tools~\cite{ball2001slam,henzinger2002blast}.

\subsection{Implications for Compiler Design}
Compiler writers should treat path awareness, context sensitivity and field sensitivity as first-class requirements---echoing the trajectory from classical PRE~\cite{morel1979global,kennedy1999partial} through SSA-based formulations~\cite{cytron1991efficient} to modern TACO-style architecture-aware optimization~\cite{xue2006lifetime,lin2024compiler}. The five scalability techniques transfer to other analyses.

\subsection{Limitations}
The front-end covers a substantial Java subset; C++/Python/Rust need additional parsers. Reflection and dynamic loading are handled conservatively. Concurrency and complex exceptions are approximated. These limitations yield safe but possibly incomplete results, similar to conservative choices in early interprocedural PDE~\cite{chatterjee2005interprocedural}.

\subsection{Practical Role}
\textsc{ModernPDE} is a research test-bed and teaching vehicle, complementary to formal verification of PDE transformations~\cite{rinard2026nexis} and to recent dead-iteration elimination~\cite{bastoul2025dead}.

\section{Threats to Validity}
\label{sec:threats}

\paragraph{Internal validity.}
Bugs could bias results; mitigated by unit tests, reviews, and manual checks on small programs.

\paragraph{External validity.}
The suite is diverse but cannot cover every domain or language beyond the supported subset.

\paragraph{Construct validity.}
Precision/recall omit maintainability of transformed code; human labeling may introduce subjectivity.

\paragraph{Reliability.}
Open-source release and detailed setup enable replication.

\paragraph{Statistical validity.}
Ten replications and warm-up runs reduce noise; larger samples remain desirable.

\section{Conclusion}
\label{sec:conclusion}

We presented \textsc{ModernPDE}, a scalable framework for interprocedural path-aware partial dead-code elimination. Integrating context-sensitive call graphs, field-sensitive memory modeling, and five engineering techniques yields 96.2\,\% precision and 91.4\,\% recall while cutting analysis time by 78\,\% versus exhaustive enumeration. The finding that 42.1\,\% of variables are partially dead confirms the practical importance of PDE beyond classical single-function formulations~\cite{knoop1994partial,bodik1998efficient}.

Future work includes front-ends for more languages, JIT integration, ML-guided path pruning, and compact liveness representations. We invite the community to build on the open-source release.
